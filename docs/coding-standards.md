# 📑 Coding standards

The judgment calls a tool cannot make for you.

> [!NOTE]
> Everything mechanical is already enforced: TypeScript (`strict`, `strictTemplates`), ESLint and
> Prettier decide formatting, import order and most type-safety rules. Run them rather than
> reasoning about them: `npm run build`, `npm run lint`, `npm run format`.

## 🛡️ Type safety

- **The type system is the cheapest test suite.** Prefer a build-time error to a runtime one.
- **No `any`.** Reach for `unknown` and narrow.
- **Validate external data at the boundary, once.** The API route checks `:age` against a pattern
  before the rule sees it; past that point the value is trusted.
- **A non-null assertion or a cast is a smell.** `!` usually means control-flow analysis cannot
  follow the code, so restructure it. A test double is the one place a cast is fine.
- **Make illegal states unrepresentable.** A discriminated union (the `Result` in
  `web/src/app/app.ts`) beats a set of booleans and optional fields.
- **Prefer `undefined` to `null`** for an absent value, except where an API dictates `null`:
  Signal Forms models an empty number input as `null`, and `[attr.x]="null"` removes an attribute.
- **Prefer a string-literal union to an `enum`**, and `type` to `interface`.

## 🧊 Declarative and immutable

- `const`, spread and `map` / `filter` / `find` over `let`, `push` and assignment.
- Expressions over statements: `? :`, `??` and `?.` say "this is a value".
- **Derive state, don't synchronize it.** In Angular that means `computed()` for anything computable
  from other signals, `linkedSignal()` for state that resets when its source changes, and `effect()`
  only to reach outside the reactive graph.
- Classes where Angular needs them (components, services), kept stateless where possible, with
  `readonly` fields and dependencies injected.

## ⚠️ Errors

- **Expected failures belong in the return type**: `datingRange` returns `undefined` for "no range",
  it does not throw. Reserve `throw` for the exceptional.
- **Don't mask errors.** Log or rethrow what you catch, and keep `try` blocks small.
- **An HTTP error is a Problem Details body** (RFC 9457, `application/problem+json`), as in
  `api/src/app/api/story/[age]/route.tsx`.

## ⛓️ Promises

- `async` / `await` over `.then()` chains; `Promise.all` for independent work.
- **One exception to "await freely"**: nothing may be awaited between a click and
  `navigator.share()`, because the browser opens the share sheet only during the click's user
  activation. See the [web README](../web/README.md#-sharing).

## 🅰️ Angular

The Angular CLI MCP server's `get_best_practices` (workspace `web/`) returns the guide for the
installed version. In this repo:

- **Standalone, zoneless, `OnPush` by default.** Don't set `standalone: true` or
  `changeDetection`; both are the default.
- **Signals for state**, `input()` / `output()` / `model()` instead of decorators, `inject()` instead
  of constructor parameters, `host: {}` instead of `@HostBinding` / `@HostListener`.
- **Signal Forms** (`@angular/forms/signals`) for forms, **`httpResource`** for reads.
- **Native control flow** (`@if`, `@for`, `@let`); no `CommonModule`, `ngClass` or `ngStyle`.
- **`@Service()`** for a singleton service.
- **Files are named after what they hold**, without a type suffix: `range-card/range-card.ts`
  exports `RangeCard` with the selector `app-range-card`, and `story-share.ts` exports the service
  `StoryShare`. Component styles go in the component's own `.scss` file.

## ▲ Next.js

Next.js 16 differs from older versions. Read the docs bundled at `api/node_modules/next/dist/docs/`
before using an API from memory.

- **Route handlers only**: no pages, no React on the client. A new endpoint goes under
  `api/src/app/api/`; a file at a fixed path (`/og-image.png`) is a folder of that name in
  `api/src/app/`.
- **Draw at build time when the input set is finite**: `generateStaticParams`, or
  `dynamic = 'force-static'` for a route without parameters. Reading the request in such a handler
  turns it back into a function call per request.
- **Typed route context**: `RouteContext<'/api/…'>` is generated by Next.js, and `params` is a
  `Promise`.
- **The Node.js runtime** (the default). The story image reads its fonts from disk.

## 🎨 Styling

- **Use the CSS custom properties** in `web/src/styles.scss` for every hue, never a hex or `rgb()`
  literal in a component; `color-mix()` makes a transparent one. White and black shadows are the
  exception.
- **WCAG AA contrast**: small text uses the 600+ shades (the 500s fall short on the tinted cards),
  and white text only goes on the 600 shades.
- **Animations respect `prefers-reduced-motion`**, which `styles.scss` handles globally; an element
  that appears uses `animate.enter="fade-in"`.

## 🏷️ Naming

- A good name removes the need for a comment. Avoid generic names (`data`, `item`).
- Plural for collections, singular for single values, predicates for booleans (`isAge`).
- `camelCase` values, `PascalCase` types and classes, `UPPER_CASE` shared constants (`MAX_AGE`),
  `kebab-case` files and folders.
- American English everywhere: identifiers, comments, copy.

## 🧰 Tooling

- Prefer modern ECMAScript and TypeScript over workarounds; the runtime baseline is current.
- Don't commit `console.log`; `console.error` is for real errors.
- Fix the code rather than disabling a lint rule. When a disable is genuinely right, scope it to one
  line and say why.
